# TIL - 2026-02-15

## 잘한 점
- 상황: `prod` 실행에서 schema validation 오류가 연속 발생함.
- 액션: 로그에서 실패 컬럼(`cart_items.product_id`, `products.price`)을 정확히 식별하고 SQL 스키마를 코드 타입과 일치시킴.
- 자기 평가: 원인-조치 연결이 명확했고, 재현/검증까지 당일 완료함.

## 개선점
- 문제: 초기 스키마 작성 시 엔티티 타입(`Long`, `double`)과 DB 타입 정합 검증을 선행하지 않음.
- 원인: dev 기준 동작만 먼저 확인하고 prod validate 조건을 늦게 확인함.
- 다음 액션: 스키마 변경 시 "엔티티 타입 매핑 체크리스트"를 먼저 적용하고, dev 확인 후 바로 prod 검증을 수행.

## 배운 점
- `ddl-auto=validate`는 운영 안정성 관점에서 필수적인 사전 차단 장치다.
- JPA 타입 매핑 불일치는 dev에서 지나가도 prod에서 반드시 드러난다.
- Workbench 연결 탭은 SQL 파일이 아니므로, 실제 실행은 스크립트 파일 탭 기준으로 관리해야 혼동이 줄어든다.
