# 개발 작업 체크리스트

## 목적
- 작업 전에 범위와 완료 기준을 정해 재작업을 줄인다.
- 구현, 검증, 기록 순서를 남겨 나중에 같은 작업을 다시 확인할 수 있게 한다.

## 작업 시작 전
- [ ] 작업 대상 파일을 확인했다.
- [ ] 변경하지 않을 영역을 정했다.
- [ ] 완료 기준을 1줄로 적었다.
- [ ] 필요한 참고 문서를 확인했다.
- [ ] 기능 코드 변경이 필요한지, 문서 정리만 필요한지 구분했다.

## 문서/설명 정리
- [ ] 무엇을 바꾸는지 적었다.
- [ ] 왜 바꾸는지 적었다.
- [ ] 언제 이 기준을 적용하는지 적었다.
- [ ] 어떻게 검증할지 적었다.
- [ ] 어려운 용어가 있으면 쉬운 설명을 붙였다.

## 검증
- [ ] 프론트 린트 또는 빌드를 실행했다.
- [ ] 백엔드 컴파일 또는 테스트를 실행했다.
- [ ] 한글 깨짐 점검을 실행했다. (`scripts/check-korean-garbled.ps1`)
- [ ] 실패한 검증이 있으면 원인과 제한사항을 기록했다.

## 기록
- [ ] 일일 로그에 변경 결과를 남겼다.
- [ ] 새 학습 문서를 만들었다면 인덱스에 연결했다.
- [ ] 남은 작업이나 사람이 직접 확인할 항목을 적었다.
