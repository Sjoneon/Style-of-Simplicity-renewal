# Codex 사전점검 체크리스트 (누락 방지)

## 목적
- 구현 전에 설명/의사결정/완료기준을 먼저 고정해서 재작업을 줄인다.
- 초보자도 따라올 수 있게 `설명 -> 구현 -> 검증 -> 기록` 순서를 강제한다.

## 작업 시작 전 필수 확인
- [ ] 구현 전에 학습용 설명 파일을 먼저 만들었는가
- [ ] 설명 순서를 `무엇/왜/언제/어떻게`로 작성했는가
- [ ] 어려운 용어에 쉬운 설명을 붙였는가
- [ ] 오늘 작업 대상 파일 경로를 미리 적었는가
- [ ] 완료 기준(Definition of Done)을 1줄로 적었는가

## 피드백 반영 시 필수 확인
- [ ] 기존 설명의 오류/누락을 먼저 명시했는가
- [ ] 수정 코드를 실제로 반영했는가
- [ ] 무엇이 어떻게 바뀌었는지 비교 설명했는가
- [ ] 수정 이유를 쉬운 말로 설명했는가
- [ ] 관련 학습 문서를 함께 업데이트했는가

## 검증 단계 필수 확인
- [ ] 프론트 린트/빌드 또는 해당 스택의 정적 검증을 실행했는가
- [ ] 백엔드 컴파일/테스트 또는 최소 실행 검증을 했는가
- [ ] 깨진 한글 패턴 점검을 실행했는가 (`scripts/check-korean-garbled.ps1`)
- [ ] 실패한 검증이 있으면 원인과 제한사항을 기록했는가

## 사용 규칙
- 체크리스트 항목이 하나라도 미체크면 구현 진행 금지
- 구현 후에는 일일 로그(`docs/daily/YYYY-MM-DD.md`)에 결과를 반드시 남긴다
