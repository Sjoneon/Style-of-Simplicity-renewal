# 모의 결제창 + 보안 가드 적용 (2026-04-30)

## 무엇
- 실제 청구가 발생하지 않는 `모의 결제창`을 프론트엔드에 추가한다.
- 적용 화면:
  - `frontend/src/pages/ProductDetailPage.jsx` (바로 주문)
  - `frontend/src/pages/CartPage.jsx` (장바구니 주문)
- 신규 컴포넌트:
  - `frontend/src/components/payment/MockPaymentDialog.jsx`

## 왜
- 포트폴리오/리허설 목적상 결제 UX는 필요하지만 실제 과금은 발생하면 안 된다.
- 결제 관련 입력은 민감정보이므로, 테스트 단계에서도 최소 수집/최소 보관 원칙을 지켜야 한다.

## 언제
- 실제 PG(결제대행) 연동 전, 주문 플로우를 사용자에게 시연해야 할 때
- 테스트 환경에서 결제 성공/실패 UX를 먼저 검증해야 할 때

## 어떻게
1. `바로주문/장바구니주문 -> 주문서(배송지/요청사항/결제수단) -> 모의 결제 다이얼로그` 순서로 구성한다.
2. 다이얼로그에서 카드정보 형식만 검증하고, 서버에는 카드 원문을 보내지 않는다.
3. 서버로 넘기는 정보는 `모의결제 성공 여부`와 `마스킹된 카드번호` 같은 비민감 최소값으로 제한한다.
4. 결제창에 `테스트 결제(실청구 없음)` 문구를 고정 표시한다.
5. 결제 완료/취소/실패는 기존 토스트/에러 흐름을 재사용해 다른 기능 영향 없이 연결한다.

## 보안 원칙(이번 범위)
- 카드 원문(전체 번호/CVC)은 저장/로그 출력/서버 전송 금지
- 다이얼로그 종료 시 입력값 즉시 초기화
- 자동완성 비활성화(`autoComplete="off"`), 숫자 입력 제한
- 테스트 카드 패턴(예: `4242...`)만 허용해 실사용 카드 오입력 위험 축소

## 쉬운 용어 설명
- PG: 카드사 대신 결제를 처리해 주는 외부 서비스
- 모의 결제: 돈이 빠져나가지 않는 테스트용 결제 흐름
- 마스킹: 민감정보 일부를 `****`로 가려서 노출을 줄이는 방법
