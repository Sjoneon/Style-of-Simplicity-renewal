# 2026-03-04 홈 탐색 탭 동적 관리 학습

## 무엇
- 홈 화면의 탐색 탭(예: 처음 시작, 선물, 신상)을 코드에 고정하지 않고, 판매자가 직접 추가/수정/삭제할 수 있게 구조를 바꾼다.
- 상품은 고정 boolean 5개(`showInStarterTab` 등) 대신 `discoveryTabKeys` 배열로 어떤 탭에 노출될지 저장한다.
- `랭킹`은 탭 관리 대상이 아니라 시스템 탭으로 유지하고, 판매량(`soldCount`) 내림차순으로 노출한다.

## 왜
- 신상/기획전 성격 탭은 시간이 지나면 의미가 바뀌므로 운영자가 즉시 교체할 수 있어야 한다.
- 고정 탭 방식은 새로운 기획(예: `김PD 추천`)을 반영하려면 코드 수정/배포가 필요해서 운영 속도가 느리다.
- 탭 정의(메타데이터)와 상품-탭 매핑을 분리하면 UI 확장과 운영 변경이 쉬워진다.

## 언제
- 리뉴얼 로드맵 5단계(핵심 화면 마이그레이션)에서 메인 화면 운영 기능을 실사용 수준으로 올릴 때 적용한다.
- 특히 홈 진열 정책이 자주 바뀌는 운영 단계에서 우선 적용 가치가 크다.

## 어떻게
1. 백엔드에 `discovery_tabs` API(CRUD)를 두고, 판매자 권한에서만 관리 가능하게 한다.
2. 상품 저장/수정 API에서 `discoveryTabKeys`를 함께 받아 저장한다.
3. 홈 화면은 `GET /api/v1/discovery-tabs` 결과를 탭 UI로 렌더링한다.
4. 판매자 대시보드에 탭 관리 UI(추가/수정/삭제, 활성/비활성)와 상품별 탭 연결 UI를 둔다.
5. 기존 데이터 호환을 위해 과거 boolean 필드 값은 fallback으로만 사용하고, 신규 저장은 `discoveryTabKeys`를 기준으로 한다.

## 용어 쉬운 설명
- discovery tab: 홈에서 고객이 클릭하는 큰 분류 탭.
- tab key: 탭의 내부 식별자(예: `new`, `gift`). 화면 문구(label)와 분리해 관리한다.
- fallback: 새 데이터가 없을 때만 예전 값으로 임시 대체하는 안전장치.

## 완료 기준(Definition of Done)
- 판매자가 대시보드에서 홈 탐색 탭을 추가/수정/삭제한 결과가 홈 탭 UI와 상품 노출에 즉시 반영된다.
