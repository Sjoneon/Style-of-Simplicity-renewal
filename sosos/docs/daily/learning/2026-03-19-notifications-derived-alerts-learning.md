# 2026-03-19 알림 페이지 1차 구현 학습

## 무엇
`/notifications` 페이지를 실제 알림 페이지로 확장한다.
이번 1차 범위는 아래 3종 알림이다.
- 재입고 알림
- 할인 알림
- 주문 상태 변경 알림

작업 대상 파일
- `frontend/src/pages/NotificationsPage.jsx`
- `frontend/src/services/notificationApi.js` (신규)

완료 기준(DoD)
- 알림 페이지에서 3종 알림 목록을 확인할 수 있다.
- 알림은 `전체/재입고/할인/주문상태` 필터로 나눠 볼 수 있다.
- 이전 스냅샷 대비 변화가 있을 때만 새 알림이 생성된다.
- 일반 사용자 계정에서만 알림이 생성되고, 401은 로그인 이동으로 처리된다.

## 왜
현재 페이지는 안내 문구만 있고 실제 알림 데이터가 없다.
하지만 DB에 Notification 테이블이 아직 없으므로, 백엔드 모델 설계 전 단계에서 화면과 사용자 흐름을 먼저 검증할 필요가 있다.

그래서 1차는 "파생형 알림"으로 구현한다.
- 파생형 알림: 기존 데이터(주문/상품)를 조합해서 만드는 임시 알림 방식
- 장점: 빠르게 UX 검증 가능
- 한계: 서버 저장형(읽음 동기화, 다중기기 동기화)은 아직 불가

## 언제
- 마이페이지 MVP와 계정관리 연동이 끝난 직후
- 로드맵의 다음 항목인 알림(`/notifications`) 1차 구현에 착수하는 시점

## 어떻게
1. 알림 계산 서비스(`notificationApi.js`)를 만든다.
   - 주문/상품 데이터를 불러온 뒤 사용자 관심 상품(장바구니/주문 상품) 기준으로 스냅샷 비교
   - 변화 이벤트를 알림 객체로 정규화
2. `NotificationsPage.jsx`에서 알림을 로드한다.
   - 필터/요약/읽음 처리 UI 추가
   - 읽음 상태는 로컬 스토리지에 저장
3. 세션 만료(401)와 계정 타입 분기를 넣는다.
4. 린트/빌드 검증 후 일일 로그에 기록한다.
