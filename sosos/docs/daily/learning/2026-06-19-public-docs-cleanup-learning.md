# 공개 문서 정리 작업 학습

## 무엇
- 공개 저장소에 남길 문서와 로컬에만 보관할 문서를 나누는 작업이다.
- 이번 작업 대상은 `README.md`, 로드맵, 작업 보드, 작업 요약, 개발 체크리스트, `.gitignore`, 내부 작업 운영 문서이다.
- 완료 기준: 실행 로직 변경 없이 공개 문서에는 프로젝트 설명과 검증 기록만 남기고, 내부 작업 운영 문서는 `_local_archive/ai-workflow-docs/`에 보관한다.

## 왜
- 공개 포트폴리오에는 실행 방법, 구현 범위, 운영 기록처럼 평가자가 확인할 정보가 먼저 보여야 한다.
- 내부 작업 규칙이나 대화형 작업 절차는 프로젝트 기능 설명과 목적이 달라 공개 문서에 섞이면 읽는 사람이 핵심을 파악하기 어렵다.
- 기능을 숨기거나 과장하지 않고, 실제 구현된 내용과 남은 제한사항을 짧게 정리하는 것이 목적이다.

## 언제
- 저장소를 공개하거나 포트폴리오 링크로 공유하기 전에 정리한다.
- 기능 코드가 아니라 문서 톤과 보관 위치를 정리할 때 적용한다.
- 빌드, 배포, 테스트에 필요한 설정 파일은 이동하지 않는다.

## 어떻게
- `git status`와 참조 검색으로 현재 변경 상태와 이동 가능 여부를 먼저 확인한다.
- 내부 작업 운영 문서는 `_local_archive/ai-workflow-docs/`로 이동하고, `_local_archive/`는 `.gitignore`에 추가한다.
- 공개 문서는 실제 구현 내용만 기준으로 짧게 고친다.
- 마지막에 `git status`, `git diff --stat`, `git diff --name-status`, 백엔드 컴파일, 프론트 린트/빌드, 한글 깨짐 점검을 실행한다.

## 쉬운 용어
- 공개 문서: GitHub에서 다른 사람이 볼 수 있는 README나 작업 요약 문서.
- 로컬 보관 폴더: 개인 PC에는 남지만 GitHub에는 올리지 않는 폴더.
- 실행 로직: 화면 동작, API 응답, DB 저장처럼 프로그램 결과를 바꾸는 코드.
- 참조 검색: 어떤 파일 이름이나 문장이 다른 파일에서 쓰이는지 찾아보는 작업.
