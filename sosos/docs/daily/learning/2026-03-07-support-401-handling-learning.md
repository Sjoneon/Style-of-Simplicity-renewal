# 2026-03-07 고객센터 401(세션 만료) 처리 보강 학습

## 무엇
- `/support`에서 문의 조회/등록/삭제 API가 `401`을 반환할 때 기본 Axios 문구 대신 사용자용 안내를 보여주고 로그인 페이지로 자동 이동시킨다.

### 오늘 작업 대상 파일 경로
- `frontend/src/pages/CustomerCenterPage.jsx`
- `sosos/src/main/java/com/prosos/sosos/controller/InquiryController.java`
- `sosos/docs/daily/2026-03-07.md`

### 완료 기준(DoD)
- 고객센터에서 세션 만료 상태로 API를 호출하면 `Request failed with status code 401` 대신 명확한 안내가 나오고 로그인 페이지로 이동하면 완료.

## 왜
- 현재는 기술 에러 문구가 그대로 노출되어 사용자 입장에서 원인을 알기 어렵다.
- 이미 로그인 상태로 보이더라도 서버 세션이 만료되면 401이 발생할 수 있으므로 UX 대응이 필요하다.

## 언제
- 고객문의 실사용 테스트에서 401이 실제 발생했기 때문에 즉시 보강해야 한다.

## 어떻게
1. 고객센터 페이지에 `401 전용 핸들러` 추가
- 에러 상태코드가 401이면 안내 메시지 설정
- `next` 파라미터를 유지한 채 로그인 페이지로 자동 이동

2. 문의 CRUD 공통 적용
- 목록 조회, 문의 등록, 문의 삭제의 catch 블록에서 401 핸들러를 우선 실행

3. 서버 메시지 문구 정리
- InquiryController의 상품 미존재 안내 문자열을 깨지지 않게 정리

4. 검증
- 프론트 린트/빌드
- 백엔드 컴파일

## 쉬운 용어 설명
- 401: 인증 정보(로그인 세션)가 없거나 만료되어 서버가 요청을 거절한 상태
