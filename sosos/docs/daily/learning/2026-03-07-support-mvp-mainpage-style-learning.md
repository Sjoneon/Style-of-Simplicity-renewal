# 2026-03-07 고객센터 MVP + 메인페이지 디자인 톤 맞춤 학습

## 무엇
- 오늘 작업은 `/support` 고객센터 페이지를 플레이스홀더에서 실제 기능(MVP)으로 바꾸는 것이다.
- MVP 범위는 `내 문의 목록 조회 + 문의 작성 + 문의 삭제`다.
- 디자인은 메인페이지와 같은 톤(카드형 섹션, 강한 타이틀, 정돈된 여백, 상단 하이라이트 영역)으로 맞춘다.

### 오늘 작업 대상 파일 경로
- `frontend/src/pages/CustomerCenterPage.jsx`
- `frontend/src/services/inquiryApi.js`
- `sosos/docs/daily/2026-03-07.md`

### 완료 기준(DoD)
- 일반 사용자 로그인 상태에서 고객센터 페이지에서 문의를 작성/조회/삭제할 수 있고, 비로그인/판매자 상태에서는 동작 제한이 명확히 보이면 완료.

## 왜
- 고객센터는 `work-summary.md` 기준 다음 구현 우선순위 1번이다.
- 기존 페이지는 안내 문구만 있는 상태라 실제 사용자 흐름(문의 남기기 -> 내 문의 확인)이 막혀 있다.
- 메인페이지와 디자인 결이 다르면 서비스가 분리된 느낌이 강해져서 사용자가 불안정하게 느낄 수 있다.

## 언제
- 핵심 화면 마이그레이션(P2) 진행 중인 지금 단계에서 바로 처리해야 한다.
- 이후 마이페이지/알림으로 넘어가기 전에 고객 문의 흐름을 먼저 열어야 사용자 관점의 기본 동선이 완성된다.

## 어떻게
1. API 함수 보강
- `inquiryApi.js`에 `fetchMyInquiries`, `createInquiry`를 추가한다.
- `fetchMyInquiries`: `GET /api/inquiries/user`
- `createInquiry`: `POST /api/inquiries`

2. 고객센터 페이지 상태 설계
- 로딩/에러/성공 메시지 상태를 분리한다.
- 문의 작성 폼 상태(`title`, `content`, `productId`)를 둔다.
- 삭제 중인 문의 ID를 따로 관리해 버튼 중복 클릭을 막는다.

3. 접근 제어 명확화
- 비로그인: 로그인 유도 안내 + 로그인 이동 버튼
- 판매자 로그인: 일반 사용자 전용 페이지라는 안내
- 일반 사용자 로그인: 문의 작성/조회/삭제 기능 활성화

4. 메인페이지 톤 반영
- 상단 하이라이트 카드 + 본문 카드 분리
- 메인페이지에서 쓰는 검정 계열 포인트 색과 라운드/보더 리듬 유지
- 빈 상태/오류/성공 메시지를 카드 안에서 일관되게 표현

5. 검증
- 프론트 린트/빌드 실행으로 문법, 번들 기준 문제를 확인한다.
- 결과와 제한사항을 일일 로그에 기록한다.

## 쉬운 용어 설명
- MVP: 가장 먼저 동작해야 하는 최소 기능 묶음
- 파생형 UI 상태: 화면에 필요한 정보(로딩, 성공 메시지 등)를 코드 안 변수로 분리해 관리하는 방식
- 톤 통일: 같은 서비스처럼 보이도록 색/여백/카드 형태를 맞추는 것
