# 2026-04-30 React 대형 컴포넌트 분해 학습

## 무엇
- `frontend/src/pages/SellerDashboardPage.jsx`처럼 1000줄 이상으로 커진 페이지를 **기능별 컴포넌트 + 훅 + 유틸**로 분리한다.
- 목표 기준:
  - 페이지/섹션 컴포넌트 1개 파일은 **250줄 이내**
  - 단일 함수(핸들러/유틸)는 **100줄 이내**

## 왜
- 파일이 너무 길면 수정 범위를 파악하기 어려워서 회귀 버그가 늘어난다.
- 판매자/소비자 기능을 동시에 다루는 프로젝트에서는 작은 단위 분리가 재사용성과 테스트 속도를 높인다.

## 언제
- 컴포넌트가 250줄을 넘기기 시작하거나,
- 한 파일에 "상태 + API 호출 + 렌더 UI + 폼 검증"이 동시에 몰릴 때 바로 분해한다.

## 어떻게
1. 상수/순수 유틸 먼저 분리 (`constants`, `utils`)
2. 탭/섹션 UI를 분리 (`Overview`, `Home관리`, `상품`, `주문`, `문의`)
3. 생성/수정 다이얼로그 폼을 별도 컴포넌트로 분리
4. 페이지 파일은 "데이터 주입 + 탭 라우팅"만 담당하도록 축소
5. 빌드/컴파일로 기능 회귀 여부 확인 후 서버 재기동

## 오늘 대상 파일 경로
- `frontend/src/pages/SellerDashboardPage.jsx`
- (신규) `frontend/src/components/seller-dashboard/*`
- (신규) `frontend/src/pages/seller-dashboard/*`

## 의사결정 1줄
- 무엇: 판매자 대시보드를 기능 단위 컴포넌트로 분해한다 / 왜: 유지보수성과 재사용성을 높이고 파일 길이 기준(250줄)을 맞추기 위해서.

## 완료 기준 (Definition of Done)
- 판매자 대시보드 페이지가 250줄 이내로 축소되고, 분리된 하위 컴포넌트/함수도 250/100줄 기준을 넘지 않는다.
- 소비자/판매자 핵심 화면 동작에 필요한 프론트 빌드 + 백엔드 컴파일이 성공한다.
- 백엔드/프론트 서버를 `.env` 기준으로 재가동한다.
