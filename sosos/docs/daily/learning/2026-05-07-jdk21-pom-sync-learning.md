# 무엇
- 백엔드 빌드 기준 Java 버전을 `sosos/pom.xml`에서 17에서 21로 변경했다.

## 왜
- 팀에서 합의한 런타임 기준이 JDK 21인데, 빌드 타깃이 17이면 개발/배포 기준이 어긋난다.
- 빌드 기준을 21로 맞춰야 로컬, EC2, CI 환경이 같은 기준으로 동작한다.

## 언제
- EC2 배포 준비 중, 사용자가 "JDK 21로 계속 가기로 했다"는 피드백을 준 직후 적용했다.

## 어떻게
1. `sosos/pom.xml`의 `<java.version>` 값을 `21`로 변경했다.
2. 변경 후 Maven 컴파일을 실행해 기본 빌드가 깨지지 않는지 확인했다.
3. 배포 서버(EC2)에도 JDK 21을 설치해 런타임과 빌드 기준을 동일하게 유지한다.

## 용어 쉬운 설명
- `java.version`: 프로젝트가 어떤 Java 기준으로 컴파일될지 정하는 값.
- `런타임`: 실제 서버에서 프로그램을 실행하는 Java 환경.
