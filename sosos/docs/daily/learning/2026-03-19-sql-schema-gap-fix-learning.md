# 2026-03-19 SQL 스키마 보강 학습

## 무엇
기존 `sosos/db/seed/mydb.sql` 기준 스키마와 현재 리뉴얼 코드(JPA 엔티티) 사이의 누락을 보강한다.

작업 대상 파일
- `sosos/db/seed/mydb.sql`
- `sosos/db/seed/mydb_upgrade_2026_03_19.sql` (신규)

완료 기준(DoD)
- 현재 엔티티 기준으로 누락된 테이블/컬럼이 seed SQL에 반영된다.
- 기존 DB를 초기화하지 않고도 올릴 수 있는 업그레이드 SQL이 추가된다.
- 보강 후 dev/prod에서 schema mismatch 가능성이 줄어든다.

의사결정 1줄
- 초기 구축용(`mydb.sql`)과 기존 DB 보강용(`mydb_upgrade_2026_03_19.sql`)을 분리한다. 이유: 새 설치와 기존 운영 DB 적용 방법이 다르기 때문이다.

## 왜
프론트에서 구현한 새 기능(찜, 사이즈 옵션, 탐색 탭, 메인 배너 등)은 기존 SQL 스키마에 없는 테이블/컬럼을 사용한다.
기존 SQL만으로 DB를 만들면 JPA `validate`/실행 중 오류가 발생하거나 일부 기능 데이터가 저장되지 않는다.

## 언제
- 리뉴얼 프로젝트에서 마이페이지/찜/탐색 탭 기능이 추가된 이후
- 기존 SQL로는 데이터 저장 누락 가능성이 확인된 시점

## 어떻게
1. 엔티티와 기존 SQL 스키마를 비교해 누락 테이블/컬럼 목록을 확정한다.
2. `mydb.sql`에 최신 스키마 기준으로 누락 항목을 반영한다.
3. 기존 DB용 `mydb_upgrade_2026_03_19.sql`을 만들어 `ALTER/CREATE` 보강 쿼리를 추가한다.
4. 스크립트 내부에 실행 순서와 주의사항을 주석으로 명시한다.
