# AI 추천 안정화 + 무료 API 한도 보호 학습 (2026-05-01)

## 무엇
- 일반 사용자가 평범하게 질문해도 끊기지 않고 추천이 이어지도록 `AiStylistService` 의도 해석/후보 점수 로직을 보정한다.
- 무료 AI API 한도를 고려해, 로컬 규칙 추천을 기본으로 두고 외부 API 실패/한도 초과 시에도 서비스가 멈추지 않도록 폴백 안전장치를 둔다.

## 왜
- 현재는 평범한 요청(예: 상하의 추천, 색상 중심 추천, 리셋 요청)에서도 `blocked=true`가 잘못 나와 추천이 끊기는 케이스가 있다.
- 멀티턴 대화에서 계절 변경, 카테고리 제외(“신발 빼고”), 액세서리 과다 노출 같은 사용자 의도가 누락된다.
- 무료 API는 호출량 제한(쿼터/레이트 리밋)이 있어, 매 턴 외부 호출에 의존하면 품질 저하와 장애가 발생할 수 있다.

## 언제
- AI 추천 품질 패치 직전/직후 검증 단계에서 적용한다.
- 배포 전 스모크 테스트에서 “연속 대화 3턴 이상” 시나리오를 반드시 포함해 확인한다.

## 어떻게
- 작업 파일
1. `sosos/src/main/java/com/prosos/sosos/service/AiStylistService.java`
2. `sosos/src/test/java/com/prosos/sosos/service/AiStylistServiceTest.java` (기대 동작 회귀 확인)

- 구현 순서
1. 입력 안전 처리: 빈 문자열/초장문/리셋/유해·외부몰 요청을 분리 처리
2. 의도 해석 강화: 상의·하의·외투·신발·가방·액세서리 + 제외 문구(“빼고/말고/제외”) 반영
3. 멀티턴 규칙: 최신 메시지 우선, 단 최근 문맥에서 필요한 조건(예산/체형/스타일)은 보완
4. 계절 충돌 처리: 사용자가 계절을 바꾸면 이전 계절 후보를 강하게 제외
5. 코디 기본 구성: 일반 코디 요청은 기본적으로 상의+하의를 우선 보장, 추위/계절 조건 시 외투 보강
6. 무료 API 보호: 로컬 추천을 1차로 사용하고, 외부 API는 선택적 보조로만 사용하며 실패 시 즉시 로컬 결과 반환

## 쉬운 용어 설명
- 폴백(Fallback): 원래 경로가 실패해도 서비스가 멈추지 않게 준비한 대체 경로
- 쿼터(Quota): 무료 플랜에서 일정 기간 동안 사용할 수 있는 호출량 한도
- 레이트 리밋(Rate Limit): 짧은 시간 동안 너무 많이 호출하면 막히는 제한

## 완료 기준 (DoD)
- `AiStylistServiceTest` 전수 통과
- “여름 상하의 → 겨울로 변경” 시 겨울 키워드 상품이 우선되고, 이전 계절 충돌 상품이 제외됨
- 외부 API 키가 없거나 한도 초과여도 추천 응답이 실패하지 않음
