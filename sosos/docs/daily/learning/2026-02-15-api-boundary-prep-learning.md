# 학습 설명 (구현 전) - 2026-02-15 API 경계 정리 준비

## 무엇
- API 경계 정리 전에, 서버를 같은 조건으로 반복 실행할 수 있는 준비 목록을 만든다.
- 준비 목록에는 실행 명령, 환경변수, DB 상태, 사전 확인 항목을 넣는다.
- 실제 코드 변경 전에 "실행/검증 기준"을 먼저 고정한다.

## 왜
- 경계 정리는 컨트롤러/URL/응답 형식을 건드려서, 실행 조건이 흔들리면 원인 파악이 어려워진다.
- "코드 문제"와 "환경 문제"를 분리해야 빠르게 디버깅할 수 있다.
- 같은 명령으로 dev/prod를 번갈아 확인해야 회귀(원래 되던 기능 깨짐)를 줄일 수 있다.

## 언제
- `ProductController`, `OrderController` 같은 혼합 컨트롤러를 분리하기 직전.
- `/api/v1/*` 신규 경로를 열기 직전.
- 공통 응답 포맷(`success/data/message`)을 도입하기 직전.

## 어떻게
- 1단계: 서버 실행 명령을 dev/prod로 분리해 적는다.
- 2단계: DB/환경변수 준비를 체크박스로 명확히 적는다.
- 3단계: "내가 수동으로 해야 하는 일"과 "코드 변경 후 검증"을 분리해 적는다.
- 4단계: 실제 작업할 때는 체크리스트를 위에서 아래로 체크하고 시작한다.

## 쉬운 용어 설명
- API 경계: 화면(HTML 반환)과 데이터(JSON 반환)의 분리선.
- 프로파일(dev/prod): 실행 환경별 설정 묶음.
- 스모크 테스트: 핵심 기능만 빠르게 확인하는 최소 테스트.
- 회귀: 기존에 되던 동작이 변경 후 깨지는 현상.
