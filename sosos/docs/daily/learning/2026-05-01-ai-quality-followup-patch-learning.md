# AI 추천 품질 후속 패치 학습 (2026-05-01)

## 무엇
- 어제 100회 실사용 시나리오에서 실패한 7건을 줄이기 위한 후속 품질 패치다.
- 대상은 `AiStylistService`의 의도 파싱/토큰 확장/기본 추천 보강 로직이다.

## 왜
- 기존 멀티턴 패치로 문맥 연결은 개선됐지만, 아래 누락이 남아 있었다.
  1. `아우터+신발` 조합에서 OUTER가 누락되는 케이스
  2. `블랙 컬러 위주`, `기본템 위주`, `의류만` 같은 넓은 요청에서 추천 0건
  3. `바람막이`, `운동화`처럼 자주 쓰는 단어가 카테고리 힌트에 없어서 매칭이 약함

## 언제
- 아래와 같은 입력에서 응답 품질이 흔들릴 때 적용한다.
  1. 조합 요청인데 특정 카테고리만 반복 추천될 때
  2. 추상 조건(색상/스타일 키워드) 요청 시 추천 카드가 0개일 때
  3. 한국어 생활어(운동화, 바람막이)가 의도 파싱에 반영되지 않을 때

## 어떻게
- 작업 파일
  1. `sosos/src/main/java/com/prosos/sosos/service/AiStylistService.java`
  2. `sosos/src/test/java/com/prosos/sosos/service/AiStylistServiceTest.java`
  3. `runtime-logs/ai-stylist-100-scenarios.ps1` (재검증 실행용)

- 적용 계획
  1. 카테고리/패션 용어 확장 (`운동화`, `바람막이`, `의류`, `기본템`)
  2. 색상 한글 토큰을 영문 색상 토큰으로 확장 (`블랙 -> black` 등)
  3. 스코어가 0인 넓은 패션 요청에는 기본 추천 점수를 부여하는 보강 규칙 추가
  4. 조합 요청 카테고리 보강 fallback을 상향해 누락 카테고리를 더 안정적으로 포함
  5. 단위 테스트 추가 후 100회 시나리오 재검증

## 쉬운 용어 설명
- 의도 파싱: 사용자가 뭘 원하는지(상의/하의/신발)를 코드가 해석하는 단계
- 토큰 확장: 입력 단어를 비슷한 단어까지 넓혀서 검색하는 방식
- fallback: 점수가 잘 안 나올 때 최소한의 안전한 추천을 보장하는 보조 규칙

## 완료 기준 (DoD)
- 기존 실패 7건 중 최소 6건 이상이 재검증에서 통과한다.
- `여름 하의 -> 상의도 같이` 멀티턴 정상 동작은 유지된다.
- 백엔드 테스트 + 깨진 한글 점검이 모두 통과한다.

## 피드백 반영 결과 (추가)
1. 기존 오류/누락
- 사용자가 `왜 acc만 추천해`처럼 불만을 남긴 뒤 다시 코디를 요청하면, `acc` 토큰이 다음 턴 검색에 남아 액세서리만 반복 추천되는 문제가 있었다.
- `BAG_ACC` 통합 카테고리를 `ACC`로 정규화하는 과정에서 가방 요청(`가방만 추천`)까지 손실되는 회귀가 있었다.

2. 수정 코드
- `acc만` + 불만 어투(`왜`, `아니`, `답답`)는 액세서리 제외 의도로 해석해 `excludedCategories`에 반영했다.
- 일반 코디/복장 요청(비의류 명시 없음)은 의류 중심으로 우선 추천하도록 의도 파싱을 보강했다.
- `BAG_ACC` 항목은 상품명 추론이 `BAG`/`SHOES`로 잡히면 그 구체 카테고리를 우선 사용하도록 보정했다.
- 조사 제거 토큰화(`아우터랑 -> 아우터`)와 색상 별칭 확장(`블랙 -> black`)을 유지해 조합/색상 인식 안정성을 높였다.

3. 검증
- 단위 테스트: `AiStylistServiceTest` 통과
- 100회 실사용 시나리오: `PASSED=100`, `FAILED=0`
- 깨진 한글 점검: 통과

## 2차 피드백 반영 (코디 기본 구성 + 초기화 + 후속조건)

### 무엇
- 코디 요청의 기본 구성을 `상의+하의`로 강제 보정하고, `초기화` 명령과 후속 조건 문장(예산/체형/날씨) 처리를 안정화했다.

### 왜
- 실제 사용 로그에서 `자 초기화` 후 문맥 오염, `20만원 이하` 같은 후속 턴 blocked, `의류만` 문장 오해석(ACC 노출) 문제가 반복됐다.

### 언제
- 아래 징후가 보이면 같은 방식으로 보정한다.
  1. 후속 턴이 갑자기 blocked로 떨어질 때
  2. 코디 요청인데 상·하의 조합이 빠질 때
  3. `의류만`/`~빼고` 문장에서 의도와 반대로 추천될 때

### 어떻게
1. 현재 턴 우선 파싱
- 의도 파싱은 `현재 메시지` 기준으로 하고, 히스토리는 후속 질문으로 판단될 때만 병합한다.

2. 히스토리 병합 규칙
- `BAG/SHOES`는 문맥 계승, `ACC`는 현재 턴 명시 요청 시에만 계승한다.
- 예산/체형/날씨/제외어는 "후속 조건"으로 판단해 히스토리를 유지한다.

3. 코디 기본 구성
- 일반 코디 요청에서 비의류 명시가 없으면 기본 `TOP + BOTTOM`.
- 밤/쌀쌀/계절 힌트가 있으면 `OUTER`를 추가한다.

4. 초기화 처리
- 프론트에서 `초기화/자 초기화/리셋/reset` 입력 시 로컬 대화 이력을 즉시 리셋하고 서버 호출을 막는다.
- 백엔드도 동일 명령을 안전하게 처리한다.

5. 회귀 검증
- 단위테스트 추가 + 100회 시나리오 재실행으로 `PASSED=100` 확인.

## 판매자 목록/AI 후보 소스 분리 학습

### 무엇
- 판매자 화면은 "내 상품", AI 추천은 "전체 공개 재고"라는 데이터 소스 차이를 코드에서 명확히 분리했다.

### 왜
- 같은 프로젝트 안에서도 화면 목적이 다르면 조회 범위를 명시하지 않으면, 사용자에게 "없는 상품이 왜 뜨지?" 같은 혼란이 생긴다.

### 언제
- 대시보드(소유자 관점)와 추천/검색(전체 카탈로그 관점)을 동시에 운영할 때.

### 어떻게
1. 판매자 전용 조회 API(`/api/v1/products/managed`)를 추가해 소유자 범위를 서버에서 강제.
2. 프론트 대시보드는 전용 API만 사용.
3. AI 추천은 전체 재고를 보되, 테스트/디버그 상품 패턴은 추천 후보에서 제외.
