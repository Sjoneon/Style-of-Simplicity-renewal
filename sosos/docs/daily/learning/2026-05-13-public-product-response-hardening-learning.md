## 무엇
- 공개 상품 API가 `ProductDto`를 그대로 반환하면서 판매자/운영 내부 정보까지 외부에 노출되는 문제를 줄인다.
- 소비자 화면에서 꼭 필요한 정보만 내려주는 공개용 DTO를 분리하고, 판매자 대시보드용 DTO는 그대로 유지한다.
- 변경 후 백엔드 컴파일과 프론트엔드 빌드로 주요 화면이 깨지지 않는지 확인한다.

## 왜
- 공개 상품 목록/상세 API에 `sellerId`, 전체 재고 수량, 옵션별 재고 수량, 내부 노출 탭 키, 키워드 같은 운영 정보가 포함되어 있었다.
- 이런 정보는 소비자 화면 렌더링에 꼭 필요하지 않지만, 수집되면 운영 데이터 구조와 재고 현황을 쉽게 추정할 수 있다.
- 공개 정보와 관리 정보를 DTO 단계에서 분리해야 추후 기능 확장 시에도 실수로 내부 필드를 다시 노출할 가능성을 줄일 수 있다.

## 언제
- 공개 API 응답을 보다가 판매자 내부 정보와 재고 수량이 그대로 확인된 시점에 즉시 정리한다.
- AWS 운영 구조와 판매자 기능이 정리된 뒤, 포트폴리오 마감 전에 공개 응답 최소화를 진행한다.

## 어떻게
- 공개용 `PublicProductDto`와 공개용 옵션 DTO를 추가한다.
- `ProductApiController`의 공개 목록/상세/검색/카테고리 API는 공개용 DTO를 반환하도록 바꾼다.
- 필요하면 기존 홈/상세 화면이 쓰는 필드를 `hasStock`, `soldOut`, `availableOptionIds`, `publicDiscoveryTabKeys` 같은 안전한 표현으로 바꾼다.
- 판매자 전용 `/api/v1/products/managed`와 상품 등록/수정 흐름은 기존 `ProductDto`를 유지한다.
- 검증 기준
  - `mvnw -DskipTests compile` 성공
  - `frontend npm run build` 성공
  - 홈 상품 목록/상세 화면에서 공개 응답 변경으로 인한 빌드 오류가 없을 것
