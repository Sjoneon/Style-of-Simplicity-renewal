# 2026-03-19 MyPage 계정보안 API 연동 학습

## 무엇
마이페이지의 `계정 관리` 영역에서 준비중으로 남아 있던 3가지 항목을 실제 API에 연결한다.
- 회원정보 수정: 이름/연락처/주소
- 배송지 수정: 기본 배송지 주소
- 비밀번호 변경: 현재 비밀번호 확인 후 새 비밀번호로 변경

작업 대상 파일
- `frontend/src/pages/MyPagePage.jsx`
- `frontend/src/services/userApi.js` (이미 API 함수 추가됨, 화면에서 사용)
- `sosos/src/main/java/com/prosos/sosos/controller/api/v1/UserApiController.java` (이미 API 추가됨)
- `sosos/src/main/java/com/prosos/sosos/service/UserService.java` (이미 보안 로직 추가됨)

완료 기준(DoD)
- 마이페이지에서 3개 기능이 실제 저장 동작한다.
- 비밀번호 변경 성공 시 세션이 종료되고 로그인 페이지로 이동한다.
- 401 발생 시 무한 리다이렉트 없이 1회 안내 후 로그인으로 이동한다.

## 왜
프론트 화면만 먼저 만들고 실제 보안 처리(API/검증/세션 종료)를 나중에 붙이면, 사용자에게 "변경된 것처럼 보이지만 실제 반영은 안 되는" 오동작을 만든다.

특히 비밀번호 변경은 아래를 같이 만족해야 안전하다.
- 현재 비밀번호 검증
- 새 비밀번호 정책 검증(길이/문자+숫자)
- 기존 비밀번호 재사용 방지
- 변경 후 기존 세션 무효화

그래서 계정관리는 "백엔드 보안 로직 완성 -> 프론트 연동" 순서가 맞다.

## 언제
- 마이페이지 MVP가 UI 중심으로 먼저 완료된 직후
- 사용자가 준비중 항목의 이유를 확인했고, 보안 선행 조건을 반영해 먼저 할 일을 요청한 시점

## 어떻게
1. 프론트에서 계정관리 섹션을 실제 입력 폼으로 교체한다.
2. 저장 버튼 클릭 시 기존 `userApi` 함수(`updateMyProfile`, `updateMyAddress`, `changeMyPassword`)를 호출한다.
3. 성공 시 성공 메시지를 보여주고 `refreshSession()`으로 최신 사용자 정보를 다시 동기화한다.
4. 비밀번호 변경 성공 시 백엔드에서 세션이 끊기므로 프론트는 안내 후 로그인 페이지로 이동한다.
5. API 실패 메시지는 공통 `getApiErrorMessage`로 일관되게 표시한다.
