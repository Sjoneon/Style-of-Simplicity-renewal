# 학습 설명 (구현 전) - 2026-02-19 Git 보안정보 제외 설정

## 무엇
- GitHub 푸시 시 비밀번호/로컬 시크릿이 올라가지 않도록 `.gitignore` 규칙을 보강한다.
- `application-dev.properties`에서 기본 계정/비밀번호 값을 제거해 하드코딩 노출을 막는다.
- 문서에 남아 있는 고정 자격증명 예시(`root`, `0000`)를 플레이스홀더로 바꾼다.

## 왜
- `.gitignore`가 없거나 약하면 `.env`, 로컬 설정 파일, 덤프 파일이 실수로 커밋될 수 있다.
- 설정 파일 기본값에 비밀번호가 있으면 저장소 유출 시 바로 공격 표면이 된다.
- 문서 예시라도 실제처럼 보이는 계정/비번은 복붙 실수와 재사용 위험을 키운다.

## 언제
- GitHub 첫 푸시 전.
- 환경변수/DB 설정 구조를 바꾼 직후.
- 팀/포트폴리오 공개 저장소로 전환하기 직전.

## 어떻게
- 1단계: 저장소 전체에서 비밀번호/시크릿 패턴을 검색해 노출 후보를 찾는다.
- 2단계: `.gitignore`에 `.env`, local properties, 시크릿 파일 패턴을 추가한다.
- 3단계: `application-dev.properties`의 기본 계정/비밀번호를 환경변수 강제로 변경한다.
- 4단계: 문서 내 고정 비밀번호 예시는 `<DB_PASSWORD>` 형식으로 바꾼다.
- 5단계: 재검색으로 남은 하드코딩 비밀번호가 없는지 검증한다.

## 쉬운 용어 설명
- 하드코딩: 코드/파일 안에 값을 직접 적어두는 것.
- 플레이스홀더: 실제 값 대신 넣는 자리표시자 문자열.
- 시크릿: 비밀번호, API 키, 토큰처럼 외부 노출되면 안 되는 값.

## 완료 기준(DoD)
- 저장소에 실제 DB 비밀번호가 남아 있지 않고, `.env`/로컬 시크릿 파일이 Git에 포함되지 않도록 규칙이 설정된다.
