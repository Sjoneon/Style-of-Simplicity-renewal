## 학습 설명 (구현 전)
### 무엇
- 비밀번호를 DB에 그대로 저장하지 않고 해시로 저장한다.
- DB 계정/비밀번호 같은 민감정보를 `application.properties`에서 제거하고 환경변수로 받는다.
- 설정 파일을 `dev`와 `prod`로 분리해서 로컬 개발 설정과 운영 설정을 섞지 않는다.
- Actuator는 운영에 꼭 필요한 최소 엔드포인트만 노출한다.

### 왜
- 평문 비밀번호 저장은 DB 유출 시 즉시 계정 탈취로 이어진다.
- 하드코딩된 DB 비밀번호는 코드 유출 시 바로 사고로 연결된다.
- dev/prod 설정이 섞이면 운영 배포 시 실수 확률이 커진다.
- Actuator 과다 노출은 시스템 내부 정보 노출 위험을 높인다.

### 언제
- AWS 배포 전에 반드시 끝내야 하는 1순위 작업이다.
- React/API 확장 전에 먼저 기본 보안선과 운영 설정선을 맞춰야 한다.

### 어떻게
- `PasswordEncoder(BCrypt)`를 빈으로 등록하고 로그인/회원가입 로직에서 `encode`, `matches`를 사용한다.
- 과거 평문 데이터가 있을 수 있으므로 로그인 시 1회 호환 처리 후 해시로 승격 저장한다.
- `application.properties`는 공통값만 두고, `application-dev.properties`/`application-prod.properties`에 프로파일별 설정을 둔다.
- DB URL/계정/비밀번호/Actuator 정책은 환경변수 기반으로 받는다.
- Actuator는 `health`, `info`만 외부 노출하고 상세 정보는 제한한다.
